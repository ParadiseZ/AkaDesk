# M7 显示器设置与恢复验收记录

更新日期：2026-10-11。Windows 主屏幕设置、Android 操作面板、断开恢复及持久恢复记录已接入；本机与 RMX5060 的实际切换、视频继续解码和恢复均通过。本记录对应 M7，下一里程碑为 M8 诊断与稳定性。

## 1. 已实现的链路

Android 远控操作栏的“显示设置”读取当前电脑主屏幕、驱动支持的分辨率与刷新率组合、支持的标准缩放倍率。用户选择后点击应用，收到电脑实际读回的结果；也可在会话中点击“恢复连接前设置”。设置面板开启时释放远程输入并暂停画面触控，避免操作面板时注入电脑。

显示控制沿用已认证的控制 WebSocket，不另开未经认证的接口。Windows Host 在会话开始时保存原始模式；只允许当前 Streaming 会话的控制者查询和应用，旧会话、其他控制者、已结束会话都不能修改显示设置。停止、连接清理与会话超时通过同一回收路径恢复原始模式。

显示器刷新率单位为 Hz，与视频编码帧率是两个独立参数。本轮改变显示器刷新率，视频编码帧率仍使用原有会话配置；没有新增动态视频 FPS 设置，也不进行视频编码尺寸重协商。

| 层 | 实现 |
| --- | --- |
| 协议 | `proto/display.proto`：Get/SetDisplaySettingsRequest、DisplaySettingsResponse、DisplaySettingsSnapshot；`proto/session.proto` 增加原始/请求模式 |

| 采集 | `desktop/host/windows/src/cap/mod.rs`：采集线程临时使用 per-monitor V2 DPI 上下文，结束后恢复线程上下文 |
| Host 状态 | `desktop/host/runtime/src/display/mod.rs`：会话所有权、不可变原始模式、申请模式、恢复记录与回滚 |
| Host 控制 | `runtime/src/control/mod.rs`、`service/mod.rs`、`session/mod.rs`：认证、会话绑定、清理、启动恢复、真实设备快照 |
| Android | ControlProtoCodec、HostControlSession、ControllerCoordinator；`ui/home/DisplayControls.kt` 与 ControllerHomeApp |
| 验证入口 | `runtime/tests/m7_display.rs`、`runtime/examples/m7_android_fixture.rs`、`windows/examples/display_query.rs`、M7DisplayInstrumentedTest |

`DisplaySettingsSnapshot` 同时返回：

- `current_mode`：每次读取电脑实际状态。
- `history_display_mode`：本次会话连接前的原始模式，后续多次应用不能覆盖。
- `requested_display_mode`：最近一次成功请求，首次查询时为空。
- 支持模式与缩放列表：Android 用它约束选择，电脑收到请求后仍独立校验。

请求用 envelope 的 `request_id` 对应响应。Android 只接收当前连接代次、会话 ID 和请求 ID 对应的结果；15 秒未确认后提示刷新实际结果，不自动重放设置写入。Host 读取失败也返回错误，不将“没有快照”当成成功。

## 3. Windows 行为与边界

稳定显示 ID 使用 CCD 返回的 monitorDevicePath；每次操作重新解析当前 GDI source、adapter 和 source ID，不将重启后可能变化的 source 编号作为持久身份。当前只控制被采集的主显示器；复制显示的共享 source 不开放控制。

分辨率和刷新率必须精确匹配驱动枚举的模式，应用前使用 CDS_TEST。实际应用使用 flags=0，改变当前运行模式，分辨率和刷新率不写入用户默认模式；没有“自动选择最接近模式”。这些参数的语义参考 [Microsoft ChangeDisplaySettingsExW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changedisplaysettingsexw)。保留现有位置、方向与布局，只申请分辨率/刷新率字段。

缩放使用 Windows Settings 使用的 source DPI 查询/设置包（-3/-4），隔离在原生后端并校验返回范围、当前索引与目标百分比。包布局参考原始研究 [windows-DPI-scaling-sample](https://github.com/lihas/windows-DPI-scaling-sample/blob/master/DPIHelper/DpiHelper.h)。这不是 Microsoft 公开保证的 Win32 契约，不能由本机成功推断所有 Windows 版本可用；系统不支持或返回异常时显示控制报错。普通标准倍率已实测，自定义全局 DPI 未验收。

应用后重新读回分辨率、刷新率和缩放，最多等待约 1 秒确认；切换成功后请求视频关键帧。采集使用物理像素，避免 125% 缩放时将逻辑尺寸误作实际桌面尺寸。HDR 不参与本轮控制，快照中的 HDR 字段尚未接入真实 HDR 查询。

## 4. 原始设置与失败恢复

首次实际修改之前，将稳定显示 ID 和原始模式写入 Host 数据目录的 `display_restore.pending`，同步文件后重命名为 `display_restore.json`。写入失败则不调用原生修改；已有未恢复记录不得覆盖。

连续应用成功时，原始模式始终保持连接前的值。一次申请在分辨率/缩放之间部分失败时回滚到该申请之前的实际模式，保留此前成功设置；断开时再恢复连接前的原始模式。回滚也失败时阻止后续修改，保留恢复记录供停止/恢复重试。

停止恢复只有实际读回等于原始模式才清除恢复记录。启动 Runtime 时先处理旧记录；恢复失败保留记录并发出 DISPLAY_RESTORE_FAILED 诊断，新会话不能覆盖它。设备拔出、主屏身份变化或驱动拒绝恢复时可能需要恢复原显示布局后重试，不能承诺硬件不可用时立即恢复。

清理采用 session → display 的固定锁顺序。输入、音频与显示释放都先尝试，再返回错误，避免一个恢复失败阻止其他资源释放。晚到的旧会话清理不能作用于新会话。

持久恢复验收通过“留下已提交记录、释放旧 DisplayState、创建新状态执行恢复”模拟进程中断；没有进行电脑断电或强杀完整正式 Host 的验收。

| 验证 | 结果与范围 |
| --- | --- |
| Rust 全 workspace 离线测试 | 36 通过；默认忽略 M5 音频和 M7 实机测试共 2 项，不将 ignored 计作通过 |
| 最后控制响应修复后 Runtime 单元测试 | 25 通过；M7 包含 6 项状态/持久恢复测试、1 项控制所有权拒绝测试 |
| Android debug / androidTest APK 与单元测试 | 构建通过，32 项单元测试通过，包含显示能力、协议和响应分发 |
| Windows 原生 M7 测试（显式运行 ignored） | 1 通过：实际设置、实际读回、物理像素采集、正常恢复及新状态持久恢复 |
| RMX5060 Android 实机 M7 测试 | 最终版本 1 通过，10.846 秒；真实面板操作、控制请求、持续视频解码与停止恢复 |

本机连接前为 **1920×1200、60 Hz、100%**。原生测试和手机测试实际覆盖 **1920×1080 / 60 Hz / 100%**、**1920×1200 / 48 Hz / 100%**、**1920×1200 / 60 Hz / 125%**。

手机先使用实际缩放下拉框和应用按钮，再分别发送分辨率/刷新率设置，使用面板恢复按钮恢复原始模式，最后留下 125% 缩放后停止会话。连续请求后的 history 始终等于最初原始模式。

最终实机检查从 WebRTC inbound-rtp 统计读取 framesDecoded，四次改变后的计数分别为 **9→45、45→48、48→51、53→56**，每项均继续解码至少 3 个新帧。统计证明切换后继续解码，不代表长期流畅度或其他编码器均已验收。

隔离 Host 停止后的原生检查：`restored=true`，`journalRemaining=false`，实际模式回到 **1920×1200、60 Hz、100%**。测试配对/历史已移除，临时 ADB 反向转发已移除。正式用户的 Host 数据没有用作测试目录。

未验收：Linux 显示控制、多显示器/复制/旋转复杂布局、HDR、自定义全局缩放、显示器拔插、其他显卡/Windows 版本、长期网络波动、HEVC 切换后的恢复与游戏场景。本轮完成当前 Windows 普通主屏控制闭环，这些兼容场景仍需单独验收。

## 6. 重跑入口

使用本地全局 Cargo 和项目 Gradle wrapper，无需下载 Node/pnpm。Rust 命令在 `desktop/host` 执行，运行本机二进制前将项目 FFmpeg DLL 目录加入 PATH；本机 capture 测试需要可访问当前交互桌面。

```powershell
$env:RUSTC_WRAPPER=''
$env:CARGO_BUILD_RUSTC_WRAPPER=''
$env:PATH='D:\Project\AkaDesk\third_party\ffmpe-win64-gpl-shared\bin;' + $env:PATH
cargo test --workspace --offline
# 会临时切换真实主显示器，结束后恢复；仅在准备好实际桌面时显式执行
cargo test -p host-runtime --test m7_display --offline -- --ignored --nocapture --test-threads=1
```

Android 构建入口（`android` 目录）：

```powershell
.\gradlew.bat --offline :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
```

手机联调使用 `cargo build -p host-runtime --example m7_android_fixture --offline` 后运行 example，参数必须是一个尚不存在的新隔离目录。Fixture 监听 46671，生成 `android_fixture.json`（含临时 Host ID、验证码，作为私有本地测试产物）。对明确选择的 ADB 设备反向转发 tcp:46671、安装 debug/test APK，回到手机桌面后运行：

```text
am instrument -w -r -e class top.akadesk.app.controller.M7DisplayInstrumentedTest -e m7HostId <fixture-host-id> -e m7PairCode <fixture-code> top.akadesk.app.test/androidx.test.runner.AndroidJUnitRunner
```

不传 fixture 参数时此测试跳过，不能当作实机通过。Fixture 180 秒自动停止，也可创建隔离目录的 `stop` 文件。停止后检查 `final_display.json` 的恢复结果；如恢复失败保留目录和恢复记录，不直接删除。完成后移除 tcp:46671 反向转发。真实测试前应确认显示器有替代分辨率、刷新率与标准倍率，否则测试会失败，不能将缺少可测模式解释为通过。
