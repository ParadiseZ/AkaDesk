# 12-音频链路设计

## 1. 文档目的

本文档单独定义 AkaDesk V1 的音频主链路，收拢以下内容：

- 被控端系统音频采集策略
- `Opus` 音频编码与传输边界
- 主控端与被控端两侧静音控制
- `history_audio_output_setting` 的记录与恢复
- 运行时动态修改规则

本文档不展开：

- 视频链路
- 输入链路
- 完整配对流程
- V2 文件传输

## 2. 文档位置

- 文档文件：`docs/12-音频链路设计.md`
- Host Runtime 音频编排：`desktop/host/runtime/src/audio/`
- Host Contracts 音频抽象：`desktop/host/contracts/src/audio/`
- Windows 平台实现：`desktop/host/windows/src/audio/`
- Android 主控端播放与静音控制：`android/`

## 3. V1 范围

V1 音频链路固定为：

- 音频 codec：`Opus`
- 被控端系统音频采集：当前输出设备 `loopback capture`
- 被控端本地静音：支持
- 主控端本地静音：支持
- 会话断开后恢复连接建立时的音频输出设置：支持

V1 明确不做：

- 独立虚拟输出设备策略
- 单独的音频传输开关
- 多路混音
- 麦克风采集

## 4. 核心术语

- `history_audio_output_setting`
  - 连接建立时记录的被控端音频输出设置快照
- `mute_controlled_local_playback`
  - 被控端本地静音运行开关
- `mute_controller_local_playback`
  - 主控端本地静音播放开关

## 5. 主链路

V1 音频主链路按下面这条路径工作：

`Windows Output Device -> loopback capture -> runtime/audio -> Opus -> WebRTC -> Android decode -> controller local playback`

职责分工：

- `windows/audio`
  - 读取当前输出设备
  - 建立 loopback capture
  - 应用或取消被控端本地静音
  - 恢复 `history_audio_output_setting`
- `runtime/audio`
  - 编排采集、编码、停止、恢复
  - 管理会话内静音控制
  - 对外暴露稳定状态和错误
- `Android Controller`
  - 播放远端音频
  - 本地切换 `mute_controller_local_playback`

## 6. 被控端采集策略

V1 固定策略：

- 优先在当前输出设备上做 `loopback capture`
- 不切换到独立虚拟输出设备
- 不因为主控端本地静音而停止采集或编码

原因：

- 配置更轻
- 用户理解成本更低
- 与当前 Sunshine 类产品实际使用方式更接近

## 7. 静音控制

## 7.1 被控端静音

`mute_controlled_local_playback` 的语义是：

- 主控端下发到 Host Runtime
- Host Runtime 转给平台音频实现
- 作用于被控端本地播放
- 不停止音频采集
- 不停止音频编码
- 不影响主控端继续接收声音

它必须支持：

- 会话建立时带初值
- 会话运行中动态修改

## 7.2 主控端静音

`mute_controller_local_playback` 的语义是：

- 只作用于主控端本地播放
- 不进入 Host 控制协议
- 不通知被控端
- 不停止被控端采集
- 不停止传输
- 不触发 Host 重协商

它也必须支持：

- 会话运行中动态修改
- 即时生效

## 8. 音频输出设置恢复

在第一次会话接管被控端音频输出设置前，必须记录：

- 默认输出设备
- 本地静音状态
- 需要恢复的音量相关设置

该快照统一命名为：

- `history_audio_output_setting`

恢复规则：

- 正常断开时恢复
- 被控主动断开时恢复
- 异常断开时也应尽力恢复

恢复顺序建议：

1. 停止音频采集
2. 释放会话内音频资源
3. 恢复 `history_audio_output_setting`
4. 上报最终会话关闭事件

## 9. 运行时动态修改

V1 音频链路运行中允许动态修改的只有两项：

- `mute_controlled_local_playback`
- `mute_controller_local_playback`

V1 不通过运行时修改去做：

- 音频 codec 切换
- 音频传输开关
- 采样率重协商
- 声道数重协商

## 10. 协议与数据结构落点

协议侧：

- `AudioPreference`
  - `codec`
  - `sample_rate`
  - `channels`
  - `bitrate_kbps`
  - `mute_controlled_local_playback`

本地侧：

- `mute_controller_local_playback`
  - 放在主控端本地播放控制
  - 不进 Host 控制协议

恢复侧：

- `history_audio_output_setting`
  - 放在 Host Runtime SessionContext 与平台音频恢复路径中

## 11. contracts 落点

`audio/` 至少需要覆盖：

- `list_audio_devices()`
- `get_default_output_device()`
- `get_audio_capabilities(device_id)`
- `capture_audio_output_setting()`
- `prepare_audio_capture(request)`
- `start_audio_capture(request)`
- `stop_audio_capture(handle)`
- `set_controlled_local_playback_muted(muted)`
- `restore_audio_output_setting(snapshot)`

## 12. 状态与诊断

建议重点关注这些事件：

- 音频采集启动成功
- 音频采集启动失败
- 被控端静音开关应用成功
- 被控端静音开关应用失败
- 音频输出设置恢复成功
- 音频输出设置恢复失败

建议保留这些诊断结果：

- `last_audio_restore_result`
- 最近一次音频相关错误
- 最近一次被控端静音切换结果

## 13. 本次结论

V1 音频设计已经收敛成最小闭环：

- 只做 `Opus`
- 只做当前输出设备 `loopback capture`
- 只保留两端静音控制
- 两端静音都支持运行时动态修改
- 断开时必须恢复 `history_audio_output_setting`
