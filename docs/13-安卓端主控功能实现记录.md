# 13-安卓端主控功能实现记录

## 1. 文档目的

本文档用于记录 AkaDesk Android 主控端当前已经实际落地的功能、涉及文件、验证方式和明确边界。

它解决的是：

- 安卓主控目前到底已经做了什么
- 哪些内容只是 UI 预留，哪些已经接到真实发现和控制链路
- 后续继续补安卓端时，应该从哪些文件接着做

本文档是实现记录，不替代协议设计、状态机定义或里程碑文档。

## 2. 文档位置

- 文档文件：`docs/13-安卓端主控功能实现记录.md`
- Android 工程根目录：`android/`
- 主控页面入口：`android/app/src/main/java/top/akadesk/app/MainActivity.kt`

本记录覆盖当前已经落地的 Android 主控端内容：

## 4. 已实现功能

## 4.1 页面入口与主结构

当前 `MainActivity` 已经从默认空页面改成直接挂载主控端页面：

- `ControllerCoordinator` 作为页面状态与控制编排入口
- `ControllerHomeApp` 作为主控首页
- 页面销毁时会主动停止发现流程

对应文件：

- `android/app/src/main/java/top/akadesk/app/MainActivity.kt`
- `android/app/src/main/java/top/akadesk/app/ui/home/ControllerHomeApp.kt`

## 4.2 连接页与底部导航

当前安卓端已落地两项底部导航：

- `连接`
- `我的`

其中：

- `连接` 页顶部提供远程 ID 输入框和连接按钮
- `连接` 页内提供 `发现 / 历史 / 收藏 / 已配对` 四个 tab
- `我的` 页当前收敛为 `编码设置` 入口
- `编码设置` 为独立页面，带标题栏和返回键，不复用底部导航

当前布局已按最近一轮 Android 调整收紧为：

- 紧凑列表
- 扁平卡片
- 顶部 tab 为黑字 + 天蓝色下划线
- tab 下划线带切换动画，且至少与文字等宽

对应文件：

- `android/app/src/main/java/top/akadesk/app/ui/home/ControllerHomeApp.kt`

## 4.3 发现、历史、收藏、已配对列表

当前四个 tab 都已经接到真实列表数据或本地持久化数据：

- `发现`
  - 来自 Android NSD / mDNS 发现结果
- `历史`
  - 来自主控本地持久化的连接历史
- `收藏`
  - 来自主控本地持久化的收藏设备
- `已配对`
  - 来自主控本地持久化的配对记录

每个列表项当前都已经具备：

- 左侧系统图标
- 中间 `设备 ID + 用户名`
- 点击中间区域直接发起远控流程
- 右侧 `menu`
- `menu` 中统一提供 `连接`
- `发现` 页支持 `收藏 / 取消收藏`
- `收藏` 页支持 `取消收藏`
- `已配对` 页支持 `取消配对`
- 其它列表支持 `删除`

## 4.4 发现页下拉刷新

`发现` tab 已改成下拉刷新触发局域网重新发现：

- 发现列表区支持下拉刷新
- 刷新指示器已经从页面顶部移到 `发现` tab 的列表区域内
- 空列表时展示 `下拉发现设备`

这里不是 UI 假动作，而是会实际调用主控发现逻辑重新触发 `mDNS` 扫描。

对应文件：

- `android/app/src/main/java/top/akadesk/app/ui/home/ControllerHomeApp.kt`
- `android/app/src/main/java/top/akadesk/app/controller/ControllerCoordinator.kt`
- `android/app/src/main/java/top/akadesk/app/controller/HostDiscoveryClient.kt`

## 4.5 发起远控流程

当前安卓主控已支持两条入口：

- 从远程 ID 输入框直接发起
- 从列表项点击中间区域或菜单发起

当前连接判定逻辑为：

- 如果本地已有该设备 `pair_token`
  - 直接走 `记住后免密连接`
- 如果本地没有该设备 `pair_token`
  - 进入 `输入验证码连接`

另外还预留了一条未接完的模式：

- `等待对方允许`

这条模式目前只完成了 UI 入口和等待弹层，用于保留后续“被控同意后才进入远控”的扩展位。

## 4.6 配对、认证与重连

当前控制链路已经不是本地假状态，而是实际接了 `WebSocket + Protobuf`：

- 建立控制连接后先发送 `ControlHello`
- 若已保存 `pair_token`
  - 直接参与重连认证
- 若未通过认证
  - 进入配对流程
- 配对流程当前支持：
  - `PairingRequest`
  - `PairingChallenge`
  - `PairingConfirm`
  - `PairingResult`
- 配对成功后会保存新的 `pair_token`
- 保存成功后自动重连并再次认证
- 认证通过后会继续请求 `DeviceSnapshot`

当前验证码输入流程已经接到真实控制层消息：

- 弹出验证码输入底部弹层
- 输入验证码后调用 `confirmPairing`
- 失败会回到断开提示
- 成功会保存凭证并重走认证

对应文件：

- `android/app/src/main/java/top/akadesk/app/controller/ControllerCoordinator.kt`
- `android/app/src/main/java/top/akadesk/app/controller/HostControlSession.kt`
- `android/app/src/main/java/top/akadesk/app/controller/ControlProtoCodec.kt`
- `android/app/src/main/java/top/akadesk/app/controller/ControllerPairingStore.kt`

## 4.7 远控会话发起

当前安卓主控已经能在认证通过后主动发起远控会话请求：

- 发送 `StartSessionRequest`
- 带上 `SessionIntent`
- 带上主控选择的视频编码偏好
- 固定带上当前默认视频参数：
  - `1280x720`
  - `30 fps`
  - `4000 kbps`
  - `allow_same_codec_software_fallback = true`

会话状态当前已经接收并映射：

- `StartSessionAccepted`
- `StartSessionRejected`
- `SessionChangedEvent`

页面状态当前会跟随控制层推进：

- `NEGOTIATING`
- `PREPARING`
- `STREAMING`

说明：

- 当前已经能发起真实会话请求并接会话状态
- 但 `RemoteStreamScreen` 仍是远控中的页面骨架与状态占位
- 真实视频解码展示还没有在这个页面里落地

## 4.8 远控中的页面与断开提示

当前远控中的 Android 页面已经完成一版可联调 UI：

- 左侧主画面区域
- 右侧竖向操作栏
- 右侧功能当前包含：
  - `设置`
  - `键盘`
  - `显示桌面`
  - `断开`

断开态也已统一为单独提示弹窗：

- 标题：`远程控制已断开`
- 消息：当前连接或会话已经结束
- detail 会显示目标设备或失败原因

这部分是为了给真实环境调试先留出清晰的会话态切换反馈。

## 4.9 编码设置

当前 `我的 -> 编码设置` 已经接到主控本地偏好存储：

- 主控自己决定编码偏好
- 不再跟随被控端自动决定
- 当前可选项：
  - `H.264`
  - `H.265 / HEVC`
  - `VP8`
  - `VP9`
  - `AV1`

其中当前按实现口径：

- `H.264` 是已接到真实会话请求的调试选项
- 其它项目前仍属于预留项

编码选择会直接影响后续发出的 `StartSessionRequest.video.codec`。

## 4.10 本地持久化

当前安卓端已经把下面这些信息落到 `SharedPreferences`：

- 主控自身 `controller_device_id`
- 每台被控设备的 `pair_token`
- 配对设备列表
- 收藏列表
- 历史列表
- 主控视频编码偏好

当前持久化策略已经支持：

- 首次生成主控设备 ID
- 配对成功后保存被控端凭证
- 发现时刷新已配对设备摘要
- 取消配对时删除本地凭证
- 收藏和历史独立维护

对应文件：

- `android/app/src/main/java/top/akadesk/app/controller/ControllerPairingStore.kt`

## 4.11 调试与日志

当前安卓端已经把大部分调试信息从 UI 挪走，改成 `Logcat` 输出。

当前会记录的主要事件包括：

- 开始发现
- 发现到设备
- 连接发起
- 认证成功
- 配对要求
- 配对挑战
- 配对成功
- 快照读取
- 会话接受
- 会话状态变化
- 连接失败
- 主动断开

当前日志输出位置：

- `ControllerCoordinator` 内部 `logInfo / logWarn / logError`

说明：

- 当前日志仍写入 Android 日志系统
- 还没有做“按日期命名的文件日志”落地

## 7. 当前明确未完成项

截至本文档更新时，Android 主控端仍明确缺下面这些能力：

- 真实视频解码与画面渲染控件
- 真实音频播放与静音控制页面
- 右侧 `设置 / 键盘 / 显示桌面` 的实际控制协议
- 被控允许后再进入远控的真实认证分支
- 更完整的错误码映射与用户提示分层
- 真实设备联调下的多机型 UI 适配记录
- 以日期命名的本地日志文件

## 8. 后续继续时的建议切入点

如果下一步继续补 Android 主控，建议按下面顺序接：

1. 把 `RemoteStreamScreen` 接入真实视频渲染面板
2. 把右侧操作栏接到真实输入和显示控制协议
3. 补音频播放与本地静音
4. 把等待允许模式接到真实 Host 侧授权流程
5. 补文件日志与更细的错误诊断
