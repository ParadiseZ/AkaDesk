# AkaDesk 状态机定义

## 1. 文档目的

本文档用于把 AkaDesk V1 的正式状态机约束固定下来。

它解决的是：

- `RuntimeState` 怎么流转
- `SessionState` 怎么流转
- `Platform Adapter` 资源态怎么流转
- `Tauri UI` 展示态怎么映射
- 哪些状态允许进入
- 哪些状态禁止重入
- 失败后应该回到什么状态

本文档只定义状态机，不展开协议字段和代码实现。

## 2. 文档位置

本文档固定放在：

- `docs/06-状态机定义.md`

## 3. 状态机范围

当前需要正式定义四套状态：

1. `SessionState`
2. `RuntimeState`
3. `AdapterResourceState`
4. `DesktopUiState`

说明：

- `SessionState` 面向主控和被控共享的远控会话状态
- `RuntimeState` 面向 Host Runtime 进程生命周期
- `AdapterResourceState` 面向平台资源占用和释放
- `DesktopUiState` 面向 Tauri 桌面端展示态

这四套状态不能混用。

## 4. 设计原则

### 4.1 一套状态只服务一个关注点

禁止把以下内容混在一个枚举里：

- 进程生命周期
- 远控会话生命周期
- 平台资源生命周期
- 前端展示态

### 4.2 状态变化必须由明确事件触发

每个状态跳转都要能回答：

- 谁触发
- 为什么触发
- 成功条件是什么
- 失败后去哪

### 4.3 状态机优先少而稳

V1 不追求最细颗粒度，而追求：

- 可诊断
- 可恢复
- 不自相矛盾

### 4.4 快照优先于推导

UI 和诊断层优先消费状态快照，不靠事件流自行推导最终状态。

## 5. `SessionState` 定义

## 5.1 状态列表

V1 正式状态如下：

| 状态 | 含义 |
| --- | --- |
| `IDLE` | 当前没有活跃远控会话 |
| `DISCOVERING` | 主控正在发现被控设备 |
| `NEGOTIATING` | 已选定目标设备，正在握手、鉴权、协商 |
| `PREPARING` | Host 正在准备采集、音频、编码、显示器设置 |
| `STREAMING` | 视频、音频、输入链路已就绪 |
| `DISCONNECTING` | 正在停止链路、释放资源、结束会话 |
| `FAILED` | 当前会话异常失败，等待清理回待机 |

V1 不单独定义：

- `CONNECTED`
- `AUTHENTICATED`
- `READY_TO_STREAM`

这些都归并进：

- `NEGOTIATING`
- `PREPARING`

## 5.2 合法流转

```text
IDLE -> DISCOVERING
DISCOVERING -> IDLE
DISCOVERING -> NEGOTIATING
NEGOTIATING -> PREPARING
NEGOTIATING -> FAILED
NEGOTIATING -> IDLE
PREPARING -> STREAMING
PREPARING -> FAILED
PREPARING -> DISCONNECTING
STREAMING -> DISCONNECTING
STREAMING -> FAILED
DISCONNECTING -> IDLE
FAILED -> IDLE
```

## 5.3 非法流转

以下跳转明确禁止：

- `IDLE -> STREAMING`
- `IDLE -> PREPARING`
- `DISCOVERING -> STREAMING`
- `NEGOTIATING -> STREAMING`
- `FAILED -> STREAMING`
- `DISCONNECTING -> STREAMING`

原因：

- 跳过协商或准备阶段，会导致媒体参数、平台资源和 UI 状态不一致

## 5.4 触发条件

### `IDLE -> DISCOVERING`

触发：

- Android 主控开始局域网发现

### `DISCOVERING -> IDLE`

触发：

- 用户取消发现
- 发现超时且未选择设备

### `DISCOVERING -> NEGOTIATING`

触发：

- 主控选中被控设备并发起控制连接

### `NEGOTIATING -> PREPARING`

触发：

- 认证通过
- 若当前 `connection_method` 需要被控端本地同意，则本地同意也已通过
- 会话意图有效
- 媒体偏好已确认

### `NEGOTIATING -> FAILED`

触发：

- 鉴权失败
- 被控端本地拒绝
- 被控端本地确认超时
- 会话参数非法
- codec 不支持
- WebRTC 前置协商无法继续

### `NEGOTIATING -> IDLE`

触发：

- 用户主动取消连接

### `PREPARING -> STREAMING`

触发：

- 平台准备完成
- WebRTC offer/answer/ICE 完成可用
- 视频、音频、输入链路至少满足当前会话必需项

### `PREPARING -> FAILED`

触发：

- 采集初始化失败
- 编码器初始化失败
- 音频初始化失败
- 显示器设置应用失败且不可恢复

### `PREPARING -> DISCONNECTING`

触发：

- 准备阶段用户主动停止

### `STREAMING -> DISCONNECTING`

触发：

- 主控主动断开
- 被控主动断开
- Tauri 请求停止服务

### `STREAMING -> FAILED`

触发：

- 媒体链路异常
- 平台设备丢失
- 心跳超时
- Runtime 内部异常

### `DISCONNECTING -> IDLE`

触发：

- 平台资源已释放
- `history_display_mode` 已恢复
- `history_audio_output_setting` 已恢复
- SessionContext 已清理

### `FAILED -> IDLE`

触发：

- 错误已记录
- 平台资源已回收
- 当前会话上下文已销毁

## 5.5 重入规则

允许重入：

- `DISCOVERING`
  说明：
  可以重复收到发现结果，但状态不变。

- `STREAMING`
  说明：
  允许在 Streaming 内更新 `bitrate_kbps`、`fps`、分辨率等运行参数，但不改状态。
  这里的分辨率指目标显示器分辨率，允许通过重配或重建链路完成。

不允许重入：

- `PREPARING`
  说明：
  不能在已进入准备阶段时再次发起新的准备流程。

- `DISCONNECTING`
  说明：
  进入释放流程后不允许再启动新会话。

## 6. `RuntimeState` 定义

## 6.1 状态列表

| 状态 | 含义 |
| --- | --- |
| `STOPPED` | Host Runtime 未运行 |
| `STARTING` | Host Runtime 启动中 |
| `READY` | Host Runtime 可接受控制连接和会话请求 |
| `SESSION_PREPARING` | Runtime 已接受会话并进入准备阶段 |
| `STREAMING` | Runtime 当前存在活跃媒体会话 |
| `DEGRADED` | Runtime 仍可服务，但当前存在降级或非致命异常 |
| `STOPPING` | Runtime 正在停止 |
| `ERROR` | Runtime 发生不可忽略异常，等待恢复或退出 |

## 6.2 合法流转

```text
STOPPED -> STARTING
STARTING -> READY
STARTING -> ERROR
READY -> SESSION_PREPARING
READY -> STOPPING
SESSION_PREPARING -> STREAMING
SESSION_PREPARING -> READY
SESSION_PREPARING -> ERROR
STREAMING -> READY
STREAMING -> DEGRADED
STREAMING -> ERROR
STREAMING -> STOPPING
DEGRADED -> STREAMING
DEGRADED -> READY
DEGRADED -> ERROR
READY -> ERROR
ERROR -> READY
ERROR -> STOPPING
STOPPING -> STOPPED
```

## 6.3 状态语义

### `STOPPED`

- 进程不存在或已退出

### `STARTING`

- 日志、配置、平台实现、IPC server 尚未完全就绪

### `READY`

- Runtime 存活
- 可处理发现、鉴权、会话请求
- 当前无活跃媒体会话

### `SESSION_PREPARING`

- Runtime 已创建 SessionContext
- 正在做平台能力装配和媒体参数落地

### `STREAMING`

- 至少存在一个活跃会话
- 当前媒体主链路已工作

### `DEGRADED`

- Runtime 可继续服务
- 但出现了降级事实，例如：
  - 主控从硬解回退到同编码软解
  - 编码参数被下调
  - 某些非核心能力不可用

### `ERROR`

- Runtime 无法继续按正常路径提供当前服务
- 但进程未必立即退出

### `STOPPING`

- 正在停止 IPC、会话、平台资源和后台任务

## 6.4 关键触发

### `READY -> SESSION_PREPARING`

触发：

- 收到并接受 `StartSessionRequest`

### `SESSION_PREPARING -> STREAMING`

触发：

- Session 正式进入 `STREAMING`

### `SESSION_PREPARING -> READY`

触发：

- 准备阶段取消且资源已清理

### `STREAMING -> DEGRADED`

触发：

- 进入可恢复降级，例如同编码软解回退

### `DEGRADED -> STREAMING`

触发：

- 降级条件消失，服务恢复到正常流状态

### `STREAMING -> READY`

触发：

- 正常断开且当前无剩余活跃会话

### `ERROR -> READY`

触发：

- 异常已清理，Runtime 仍然可服务

## 6.5 禁止语义

以下情况禁止：

- `READY` 状态下宣称存在活跃媒体会话
- `STREAMING` 状态下没有任何 SessionContext
- `STOPPED` 状态下继续对外提供 IPC 服务

## 7. `AdapterResourceState` 定义

## 7.1 状态列表

| 状态 | 含义 |
| --- | --- |
| `UNINITIALIZED` | 平台资源尚未初始化 |
| `READY` | 可分配资源但当前未占用 |
| `PREPARING` | 正在查询设备、申请资源、应用设置 |
| `ACTIVE` | 正在采集、编码、音频处理或输入注入 |
| `RELEASING` | 正在释放平台资源 |
| `ERROR` | 平台资源层异常 |

## 7.2 合法流转

```text
UNINITIALIZED -> READY
READY -> PREPARING
PREPARING -> ACTIVE
PREPARING -> READY
PREPARING -> ERROR
ACTIVE -> RELEASING
ACTIVE -> ERROR
RELEASING -> READY
ERROR -> RELEASING
ERROR -> READY
```

## 7.3 语义约束

- `PREPARING` 表示正在准备显示器、采集、音频、编码相关资源
- `ACTIVE` 表示当前至少一种关键资源被会话占用
- `ERROR` 不等于进程退出，只表示平台资源层出现异常

## 8. `DesktopUiState` 定义

## 8.1 状态列表

| 状态 | 含义 |
| --- | --- |
| `BOOTING` | 桌面壳启动中 |
| `READY` | 桌面壳可操作，当前无活跃会话 |
| `CONNECTING_VIEW` | 正在建立连接 |
| `SESSION_ACTIVE_VIEW` | 正在展示活跃会话状态 |
| `ERROR_VIEW` | 向用户展示错误或恢复建议 |
| `STOPPING` | 桌面壳退出中 |

## 8.2 语义约束

- `DesktopUiState` 是展示态，不是 Host 内部会话态
- UI 不自行决定远控是否成功，只映射 Runtime 和 Session 快照
- `ERROR_VIEW` 可以在之后回到 `READY`，不表示 Host 必然退出

## 9. 状态映射规则

## 9.1 `SessionState -> DesktopUiState`

| SessionState | DesktopUiState |
| --- | --- |
| `IDLE` | `READY` |
| `DISCOVERING` | `READY` |
| `NEGOTIATING` | `CONNECTING_VIEW` |
| `PREPARING` | `CONNECTING_VIEW` |
| `STREAMING` | `SESSION_ACTIVE_VIEW` |
| `DISCONNECTING` | `SESSION_ACTIVE_VIEW` 或 `CONNECTING_VIEW` |
| `FAILED` | `ERROR_VIEW` |

说明：

- `DISCONNECTING` 时 UI 可以保持会话页直到真正回到 `IDLE`
- `DISCOVERING` 是否显示为单独页面，由前端决定，但不单独占一个 Runtime 状态

## 9.2 `RuntimeState -> DesktopUiState`

| RuntimeState | DesktopUiState |
| --- | --- |
| `STARTING` | `BOOTING` |
| `READY` | `READY` |
| `SESSION_PREPARING` | `CONNECTING_VIEW` |
| `STREAMING` | `SESSION_ACTIVE_VIEW` |
| `DEGRADED` | `SESSION_ACTIVE_VIEW` 或 `ERROR_VIEW` |
| `ERROR` | `ERROR_VIEW` |
| `STOPPING` | `STOPPING` |

## 10. 异常与恢复规则

## 10.1 可恢复异常

以下异常允许不立即终止 Runtime：

- 主控不支持目标编码硬解，回退到同编码软解
- 非关键显示器设置应用失败但媒体主链路仍可运行
- 某些诊断能力不可用

默认处理：

- `RuntimeState` 进入 `DEGRADED`
- `SessionState` 可保持 `STREAMING`

## 10.2 不可恢复异常

以下异常默认终止当前会话：

- 采集初始化失败且无替代路径
- 编码器初始化失败且无软编回退路径
- WebRTC 协商失败
- 平台资源丢失导致链路不可继续

默认处理：

- `SessionState -> FAILED`
- `AdapterResourceState -> ERROR -> RELEASING`
- `RuntimeState -> ERROR` 或回到 `READY`

## 10.3 清理后回归规则

必须满足以下条件才能从异常回到可服务状态：

- 当前 SessionContext 已销毁
- 平台资源已释放
- 错误已记录到诊断缓冲
- IPC 服务仍可工作或已恢复

## 11. V1 最小实现要求

开始开发时，最少要先把以下枚举和转移规则定死：

1. `SessionState`
2. `RuntimeState`
3. `DisconnectReason`
4. `AdapterResourceState`
5. `DesktopUiState`

最少要有以下校验：

- 非法状态跳转直接拒绝
- 关键状态变化必须写日志
- 会话结束后必须回到 `IDLE`
- Runtime 正常断开后必须回到 `READY`

## 12. 本次结论

状态机定义文档固定放在：

- `docs/06-状态机定义.md`

它解决的是“状态能不能跳、为什么跳、跳完应该处于什么一致状态”，不是“协议字段怎么写”或“代码怎么实现”。
