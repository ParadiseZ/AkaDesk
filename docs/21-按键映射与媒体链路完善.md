## 按键映射

- 方案管理：空白新建、选择、重命名、复制、删除、本地 JSON 导入导出、常用键盘和 WASD 预设。
- 编辑期间使用独立草稿，按键名称、位置、大小、不透明度、动作与视角配置一并保存；取消确认后全部丢弃。
- 单键与 2–4 动作组合支持键盘、左/右/中鼠标键和滚轮；例如 Ctrl + R + H + 右键。
- 触发方式支持按住、单击、锁定、100 ms 间隔连发。滚轮不能锁定。
- 多个映射共享同一修饰键或鼠标键时引用计数，只在最后一个持有者释放时发送抬起。
- 切换方案、打开面板、失去前台、仅观看、进入小窗和断开时释放持有输入并取消连发。
- 可移动按键支持运行时长按拖动，编辑器支持直接拖动；每键尺寸 16–100 dp、不透明度 10%–100%。
- 全局设置包括默认按钮样式、双指缩放和按键触觉反馈，单键样式优先。
- 3D 视角支持跟随移动或模拟左/右/中键按住拖动，全屏或右半屏、独立 X/Y 灵敏度、隐藏未按下按键、禁止画面双击。
- 视角移动使用新增的相对指针协议和 Windows `SendInput` 相对移动，不把绝对光标推到屏幕边缘。
- 右半屏在手势开始时确定归属，避免从左侧跨到右侧时丢失鼠标抬起。视角手势转为双指时结束持键，再进入缩放。

配置兼容旧快捷键与修饰标志；旧组合超过四个动作时保留原配置，进入选择器后明确提示移除动作才能确认。
导入限制 64 KiB、20 个方案、每方案 30 个映射；严格验证枚举、动作、唯一 ID、有限数值及归一化位置。
重复名称生成副本，最后一个方案不能删除。格式为 AkaDesk JSON，不宣称兼容 UU 的私有方案文件。
新增相对指针协议需要本轮 Host 与 Android 配套使用。

## 音频问题与修复

原实现请求 `AUDIOFOCUS_GAIN`，设置 `MODE_IN_COMMUNICATION` 并强制扬声器路由，
而固定版本 WebRTC 使用 `USAGE_VOICE_COMMUNICATION` / `STREAM_VOICE_CALL`。
这些路径会干扰其他播放器的焦点、输出路由及音量通道。

本轮移除全局焦点、模式和扬声器操作，远端播放使用 `USAGE_MEDIA`、音乐内容类型和 `STREAM_MUSIC`。
远端静音只修改本连接音轨音量，音量键使用媒体音量通道，不改全局音量。

`google-webrtc:1.0.32006` 没有媒体 AudioAttributes 配置入口，因此仅替换其 Java 播放类。
Gradle 从原 AAR 排除同名类，保留原生库和其他 API；JNI 方法签名固定版本检查及契约测试防止升级失配。
源码、BSD 许可证和变更说明位于 `android/app/src/main/java/org/webrtc/audio/`。
真机验收覆盖实际原生播放启动、并行媒体 AudioTrack 继续播放、模式/扬声器/媒体及通话音量不变；
没有把模拟并行音轨说成所有第三方 App 或厂商音频策略的全面验收。

## 帧率与延时

帧率设置会在线更新 Host 的采集轮询和编码目标。Android 读取 Host 确认结果，
同步设置 `SurfaceViewRenderer.setFpsReduction` 渲染上限，并在 API 30+ 请求 `Surface.setFrameRate`。
Surface 重建时重新应用，解绑时撤销显示刷新率请求。
该 API 请求合适的手机屏幕刷新模式，不保证硬件一定切到精确的设定 Hz；面板另外显示实际屏幕刷新率。

网络状态首项不再把 RTT 当帧延时：

| 显示项 | 数据含义 |
| --- | --- |
| 帧处理延时 | 新版统计提供的接收到解码完成均值 |
| 帧处理延时（估算） | 缺少上述统计时，抖动缓冲均值加解码均值 |
| 帧延时（播放目标） | 当前旧库的 `googCurrentDelayMs`，原生实现为 `TargetVideoDelay()` |
| 网络往返 RTT | 选中 ICE candidate pair 的 `currentRoundTripTime` |
| 解码延时 | `totalDecodeTime` / 解码帧数的区间差值 |
| 采集方式 | 当前真实后端 `GDI / BitBlt` |
| 带宽占用 | 优先连接接收字节差值，缺失时汇总音视频接收字节 |

播放目标包含缓冲、解码预算与渲染等待，不是实际采集到屏幕显示的全链路测量。
当前真机截图显示播放目标 58 ms、RTT 13 ms、解码 13.2 ms，三者分别显示。

## 静态画面降帧

Host 比较完整 BGRA 帧，画面未变时跳过编码和视频 RTP 发送，每秒编码一帧保活；
任意像素变化、尺寸变化、编码重配或关键帧请求立即恢复编码。
RTP 时间戳按单调帧时间推进，手动 H.264 packetization 保留静态间隔，
避免当前 Rust WebRTC `write_sample` 忽略 `Sample.packet_timestamp` 导致时间错位。

这降低编码和视频传输，但仍按目标帧率进行 GDI 全帧采集和比较，尚未采用 DXGI 脏区域或降低采集 CPU。
音频、控制通道、RTCP 与 ICE 保活仍有流量，不能把“画面没变”表述为完全不传数据。
UU 的私有实现无法从录屏确认；低帧率、变化检测和局部更新可以解释同类现象，但不能断言它的具体实现。
