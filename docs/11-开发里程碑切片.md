# AkaDesk 开发里程碑切片

## 1. 文档目的

本文档用于把 AkaDesk 的开发推进方式固定成“可追踪交付物切片”。

它解决的是：

- 每个阶段到底做什么
- 每个阶段到底会落哪些文件和模块
- 后期如何快速知道已经写了什么
- 哪些内容明确还没做
- 每个阶段怎么验收

本文档不替代技术选型或架构设计，而是把这些结论转成可执行的工程切片。

## 2. 文档位置

本文档固定放在：

- `docs/11-开发里程碑切片.md`

## 3. 切片原则

每个里程碑必须同时写清 6 件事：

1. 目标
2. 交付物
3. 涉及文件或目录
4. 验收标准
5. 明确不包含内容
6. 风险与后补

这样后期要回看“到底写了什么”，不靠记忆，只看：

- 交付物清单
- 涉及目录
- 验收结果

## 4. 记录规则

每完成一个里程碑，后续必须补三类记录：

### 4.1 范围账

本次计划做什么：

- 本里程碑目标
- 本里程碑边界

### 4.2 实现账

本次实际落了什么：

- 新增了哪些目录
- 新增了哪些文件
- 修改了哪些关键模块
- 新增了哪些协议、trait、状态、错误码

### 4.3 验证账

本次如何证明有效：

- 跑了哪些命令
- 做了哪些手动验证
- 没验证哪些风险

## 5. 里程碑总览

建议当前项目按下面的顺序推进：

| 里程碑 | 名称 | 最小成果 |
| --- | --- | --- |
| `M0` | 文档基线 | 技术与边界文档定稿 |
| `M1` | 协议与骨架 | `proto/` 与 `desktop/host/*` 骨架建立 |
| `M2` | 桌面壳与本地 IPC | `desktop-shell` 拉起 `host-runtime` 并建立 IPC |
| `M3` | 发现与配对 | `mDNS + WebSocket + pairing` 跑通 |
| `M4` | 视频主链路 | `H.264` 单路视频预览跑通 |
| `M5` | 音频链路 | `Opus` 音频采集与传输跑通 |
| `M6` | 输入控制 | 鼠标、滚轮、键盘注入跑通 |
| `M7` | 显示器控制与恢复 | 分辨率/缩放/FPS 修改与 `history_display_mode` 恢复跑通 |
| `M8` | 诊断与稳定性 | 日志、错误、诊断导出、降级与重连补齐 |
| `M9` | V2 文件传输 | 基础文件传输闭环 |

## 8. `M2` 桌面壳与本地 IPC

### 8.1 目标

让 `desktop-shell` 可以拉起 `host-runtime`，并建立稳定本地 IPC。

### 8.2 交付物

- `desktop-shell` 进程启动骨架
- `host-runtime` 进程入口
- `interprocess + protobuf` IPC client/server
- `GetRuntimeStatus`
- `RuntimeStatusChanged`
- `GetCapabilitySnapshot`

### 8.3 涉及目录

- `desktop/src-tauri/`
- `desktop/host/ipc/`
- `desktop/host/runtime/`

### 8.4 验收标准

- 桌面壳能拉起 Host
- Host 能建立 IPC server
- 桌面壳能拿到 `RuntimeStatus` 和 `CapabilitySnapshot`

### 8.5 明确不包含

- 远程发现
- 配对
- 会话建立
- 视频音频输入链路

### 8.6 风险与后补

- Windows 子进程管理、退出清理和日志桥接可能后补

### 8.7 范围账

- 本轮 `M2` 只打通 `desktop-shell -> host-runtime` 的进程拉起和本地 IPC 管理面
- IPC 只覆盖 `GetRuntimeStatus`、`RuntimeStatusChanged`、`GetCapabilitySnapshot`
- 不进入会话建立、发现配对、媒体链路、平台能力真实实现

### 8.8 实现账

- 在 `desktop/host/ipc/` 引入 `interprocess + prost`，把 `IpcEnvelope`、`RuntimeStatusSnapshot`、`CapabilitySnapshot` 等最小消息改成真实 Protobuf 二进制载荷
- 在 `desktop/host/ipc/src/codec/` 实现长度前缀帧编码与解码
- 在 `desktop/host/ipc/src/server/` 实现同步 local socket server，连接建立后推送 `RuntimeStatusChanged` 与 `CapabilitySnapshotChanged`
- 在 `desktop/host/ipc/src/client/` 实现同步 local socket client，支持读取启动事件并主动请求 `GetRuntimeStatus`、`GetCapabilitySnapshot`
- 在 `desktop/host/runtime/src/main.rs` 增加 `--ipc-name` 参数入口，并把 `RuntimeService` 快照挂到 IPC server
- 在 `desktop/src-tauri/src/host/` 实现 `HostSupervisor`，负责解析 `host-runtime` 路径、拉起子进程、重试连接 IPC、拉取初始快照、退出时清理子进程
- 在 `desktop/src-tauri/src/main.rs` 实现最小启动闭环，输出 `desktop-shell` 已拿到的运行态与能力摘要
- 更新 `desktop/host/Cargo.lock` 与 `desktop/src-tauri/Cargo.lock` 锁定新增依赖

### 8.9 验证账

- 在 `desktop/host/` 执行 `cargo check`，确认 `host-ipc`、`host-runtime` 及依赖可通过检查
- 在 `desktop/src-tauri/` 执行 `cargo check`，确认 `desktop-shell` 及其对 `host-ipc` 的路径依赖可通过检查
- 在 `desktop/host/` 执行 `cargo build -p host-runtime`，生成 `target/debug/host-runtime.exe`
- 在 `desktop/src-tauri/` 执行 `cargo run`，确认 `desktop-shell` 实际拉起 `host-runtime` 并输出：
  `desktop-shell bootstrap ok: supervisor_ready=true, host_state=READY_FOR_M2, runtime_status=READY_FOR_M2, supports_input=true`

## 9. `M3` 发现与配对

### 9.1 目标

跑通：

- `mDNS`
- `WebSocket`
- `ControlHello`
- `PairingChallenge`
- `pair_token`

### 9.2 交付物

- `mDNS` 服务发布
- `mDNS` 浏览
- 控制层 `WebSocket` 入口
- `ControlHello`
- `PairingRequest`
- `PairingChallenge`
- `PairingConfirm`
- `PairingResult`
- `pair_token` 本地保存与校验

### 9.3 涉及目录

- `proto/device.proto`
- `proto/pairing.proto`
- `desktop/host/runtime/`
- `desktop/src-tauri/`
- `android/`

### 9.4 验收标准

- Android 能发现 Windows 被控
- 未配对设备可显示最小摘要
- 首次配对成功后能直接重连认证

### 9.5 明确不包含

- 视频音频实时链路
- 输入注入

### 9.6 风险与后补

- 网络环境差异可能影响 `mDNS` 表现

### 9.7 范围账

- 本轮 `M3` 只打通 `Android Controller <-> Host Runtime` 的发现、控制握手、首次配对和配对后重连认证
- 控制层只覆盖 `ControlEnvelope`、`ControlHello`、`PairingRequest`、`PairingChallenge`、`PairingConfirm`、`PairingResult`、`GetDeviceSnapshot`、心跳
- 不进入视频音频实时链路、输入注入、桌面端配对管理 UI 和复杂安全加固

### 9.8 实现账

- 在 `proto/` 为跨端控制层补齐 `ControlMessageKind`、`ControlEnvelope`，并统一补上 Android Java 生成选项
- 在 `desktop/host/runtime/` 新增 `build.rs` 和生成代码入口，把 `proto/` 中的发现、配对、设备消息编译进 Host Runtime
- 在 `desktop/host/runtime/src/discovery/` 实现 `_akadesk._tcp.local.` 的 `mDNS` 发布，公开 `device_id`、`display_name`、`platform`、`hostname`、`app_version`、`control_port`、`paired`、`reachable`、`last_seen_ms`
- 在 `desktop/host/runtime/src/control/` 实现控制层 `WebSocket + Protobuf` 入口，支持 `ControlHello` 认证、首次 `PairingRequest/PairingConfirm` 配对、`pair_token` 校验重连、`GetDeviceSnapshot` 和 `HeartbeatPing/Pong`
- 在 `desktop/host/runtime/src/pairing/` 实现 Host 身份落盘、配对记录 JSON 持久化、`pair_token` 摘要校验、验证码与挑战状态管理
- 在 `android/app/` 引入 `OkHttp WebSocket` 与预生成 `protobuf-javalite` 源码，新增 `HostDiscoveryClient`、`HostControlSession`、`ControllerCoordinator`、`ControllerPairingStore`，并把 `MainActivity` 改成可扫描、连接、输入验证码、保存 `pair_token`、重连取快照的单页 `Compose` 原型
- 新增 `desktop/host/runtime/tests/m3_discovery_pairing.rs`，覆盖 Host 发布、发现、首次配对、重连认证和快照读取的最小闭环回归

### 9.9 验证账

- 在 `desktop/host/` 执行 `cargo check -p host-runtime`，确认 `mDNS`、控制层、配对持久化和 proto 生成链可通过检查
- 在 `desktop/host/` 执行 `cargo test -p host-runtime discovery_publish_pairing_and_reauth_work_together -- --nocapture`，确认同一测例内已证明：服务发布可被浏览、未携带 `pair_token` 的 `ControlHello` 被拒绝、首次验证码配对成功、重连认证成功、已认证连接可拿到 `DeviceSnapshot`
- 在 `desktop/src-tauri/` 执行 `cargo run`，确认 `desktop-shell` 仍可实际拉起 `host-runtime`，且 Host 启动日志包含控制层入口 `control ws`
- 在 `android/` 执行 `.\gradlew.bat :app:compileDebugKotlin`，确认 Android 发现与配对原型可通过编译
- 本轮未做的验证：真实 Android 设备与真实 Windows 主机在不同局域网环境下的手工联调、`mDNS` 多网卡行为、桌面端验证码展示 UI、配对撤销与过期策略

## 10. `M4` 视频主链路

### 10.1 目标

跑通 `H.264` 单路视频预览。

### 10.2 交付物

- `runtime/video`
- `CaptureQueryPort`
- `CaptureControlPort`
- `VideoEncoderQueryPort`
- `VideoEncodePort`
- Windows 采集：
  - 优先 `WGC`
  - 回退 `DXGI`
- Host 端 `H.264` 硬编优先
- Host 端 `H.264` 软编回退
- 主控端 `H.264` 硬解优先
- 主控端 `H.264` 软解回退

### 10.3 涉及目录

- `desktop/host/runtime/src/video/`
- `desktop/host/contracts/src/cap/`
- `desktop/host/contracts/src/encode/`
- `desktop/host/windows/src/cap/`
- `desktop/host/windows/src/encode/`
- `android/`

### 10.4 验收标准

- 单路视频预览稳定显示
- `VideoSessionSpec` 可观测
- 硬编失败可回退软编
- 主控硬解失败可回退同编码软解

### 10.5 明确不包含

- 极复杂自适应码控

### 10.6 风险与后补

- 第三方 crate 能力不足时，后续可能需更换实现路径
- `HEVC/VP8/VP9/AV1`

### 10.7 范围账

- 本轮 `M4` 先打通 `StartSessionRequest -> H.264 encoder prepare -> SessionChangedEvent` 的最小视频协商闭环
- Host 端只接受 `H.264` 视频偏好，并优先尝试硬编，失败后按同编码软编回退
- Android 端本轮只要求能发起视频会话准备并观察 `VideoSessionSpec`，不要求已经进入真实视频预览渲染
- 本轮不进入 `WebRTC` 视频发送轨、真实采集帧推送、Android 解码渲染和复杂码控

### 10.8 实现账

- 在 `desktop/host/.cargo/config.toml` 固定项目内 `FFMPEG_DIR`、`FFMPEG_INCLUDE_DIR`、`FFMPEG_LIB_DIR` 与 `LIBCLANG_PATH`，改为消费仓库内 `third_party/ffmpe-win64-gpl-shared`
- 在 `desktop/host/windows/` 引入 `ffmpeg-sys-next`，新增 `src/ffmpeg/` 探针与 `prepare_h264_encoder()`，验证本地 SDK 的 `H.264/HEVC/VP8/VP9/AV1` 编解码可见性，并实际打开可用 `H.264` encoder
- 在 `desktop/host/windows/src/ffmpeg/` 继续补齐 `BGRA -> YUV420P -> H.264 packet` 的最小编码冒烟路径，证明 `libavcodec + swscale` 已能直接吃一帧原始像素并输出真实编码包
- 在 `desktop/host/runtime/src/video/` 新增 `prepare_h264_session()`，按 `VideoPreference` 归一化分辨率、帧率、码率，并在会话准备阶段实际完成一次 `H.264` 测试帧编码后生成最终 `VideoSessionSpec`
- 在 `desktop/host/runtime/src/session/` 把会话注册表扩为共享状态，并持久保存当前 `SessionSnapshot`
- 在 `desktop/host/runtime/src/control/` 接入 `StartSessionRequest`、`StartSessionAccepted`、`StartSessionRejected`、`SessionChangedEvent`，把已认证控制通道真正连到 `H.264` 协商和会话快照更新上
- 在 `desktop/src-tauri/` 把阶段口径提升到 `READY_FOR_M4`，并在拉起 `host-runtime` 时优先注入项目内 FFmpeg DLL 目录
- 在 `android/app/` 为控制层补齐 `StartSessionRequest` 编码、`StartSessionAccepted/Rejected` 与 `SessionChangedEvent` 解码，并在 `MainActivity` 原型中增加 “Prepare H.264 preview” 入口和协商结果展示

- 在 `desktop/host/` 执行 `$env:LIBCLANG_PATH='D:\Program Files\LLVM\bin'; $env:PATH='D:\Project\AkaDesk\third_party\ffmpe-win64-gpl-shared\bin;' + $env:PATH; cargo test -p host-windows prepares_a_real_h264_encoder_from_local_sdk -- --nocapture`，确认本地 FFmpeg SDK 至少能实际打开一个 `H.264` encoder

- 在 `desktop/host/` 执行 `$env:LIBCLANG_PATH='D:\Program Files\LLVM\bin'; cargo check -p host-runtime`，确认 Runtime 与 `host-windows` 的 FFmpeg 接线可通过检查
- 在 `desktop/src-tauri/` 执行 `cargo run`，确认桌面壳仍能拉起 Host，且输出更新为：`desktop-shell bootstrap ok: supervisor_ready=true, host_state=READY_FOR_M4, runtime_status=READY_FOR_M4, supports_input=true`
- 在 `android/` 执行 `.\gradlew.bat :app:compileDebugKotlin`，确认 Android 控制原型的会话准备入口与协商结果展示可通过编译
- 本轮未做的验证：真实屏幕采集帧进入编码器、`WebRTC` 视频发送轨建立、Android 侧真实 `H.264` 解码预览、硬解失败后的运行中软解回退、`WGC/DXGI` 多显示器采集切换

### 11.4 验收标准
