# AkaDesk 模块与目录设计

## 1. 文档目的

本文档用于把 AkaDesk 当前阶段的模块划分、目录落位、依赖边界和初始化顺序固定下来。

它解决的是：

- 目录该怎么放
- 模块该怎么命名
- 谁可以依赖谁
- 谁不能依赖谁
- 程序启动时先起什么，后起什么

本文档不展开协议字段和数据结构细节，那些分别由：

- `docs/04-协议设计.md`
- `docs/02-数据结构设计.md`

负责。

## 2. 文档位置

本文档固定放在：

- `docs/05-模块与目录设计.md`

## 3. 顶层目录落位

当前建议的仓库顶层结构：

```text
docs/
  技术选型.md
  项目流程图.md
  数据结构设计.md
  协议设计.md
  模块与目录设计.md

android/
  app/

desktop/
  ui/
  src-tauri/
  host/
    contracts/
    ipc/
    runtime/
    windows/
    linux/

proto/
```

说明：

- `android/` 只放 Android 主控端
- `desktop/ui/` 放 Tauri 前端 UI
- `desktop/src-tauri/` 放 Tauri 宿主壳
- `desktop/host/` 放 Host Runtime 及平台相关 Rust 代码
- `proto/` 放跨端共享协议源文件

## 4. 模块总划分

当前项目按职责拆成六个一级模块域：

1. `Android Controller`
2. `Desktop UI`
3. `Tauri Shell`
4. `Host Runtime`
5. `Platform Adapter`
6. `Shared Protocol`

对应目录：

| 模块域 | 目录 |
| --- | --- |
| Android Controller | `android/` |
| Desktop UI | `desktop/ui/` |
| Tauri Shell | `desktop/src-tauri/` |
| Host Runtime | `desktop/host/runtime/` |
| Platform Contracts | `desktop/host/contracts/` |
| Platform Adapter | `desktop/host/windows/`、`desktop/host/linux/` |
| Local IPC | `desktop/host/ipc/` |
| Shared Protocol | `proto/` |

## 5.2 为什么 `adapter` 不单独做一级目录

当前口径里：

- `contracts/` 负责 trait
- `windows/`、`linux/` 负责 trait impl

所以不会再额外放一个：

- `desktop/host/adapter/`

避免命名上把“抽象接口”和“平台实现”混成一层。

## 6. Rust 模块与 crate 设计

## 6.1 Host Rust workspace

建议把 `desktop/host/` 做成一个独立 Rust workspace。

建议成员：

- `host-contracts`
- `host-ipc`
- `host-runtime`
- `host-windows`
- `host-linux`

建议目录与 crate 对应关系：

| 目录 | crate 名 |
| --- | --- |
| `desktop/host/contracts/` | `host-contracts` |
| `desktop/host/ipc/` | `host-ipc` |
| `desktop/host/runtime/` | `host-runtime` |
| `desktop/host/windows/` | `host-windows` |
| `desktop/host/linux/` | `host-linux` |

## 6.2 Tauri Rust crate

`desktop/src-tauri/` 保持一个独立 crate。

建议名：

- `desktop-shell`

它不是 Host Runtime，也不进媒体主链路。

## 6.3 crate 职责

### `host-contracts`

职责：

- 定义 trait
- 定义共享领域模型
- 定义共享错误类型
- 定义 capability/display/audio/video/input 领域抽象

不负责：

- 平台 API 调用
- IPC 传输
- 会话编排

### `host-ipc`

职责：

- 定义本地 IPC envelope 与消息分发
- 封装 `interprocess`
- 封装 Proto 消息收发
- 提供 Host Runtime server 端与 Tauri client 端基元

不负责：

- 平台能力实现
- 会话业务决策
- UI 状态管理

### `host-runtime`

职责：

- Host 生命周期管理
- 会话状态机
- 能力协商编排
- `runtime/video` 与 `runtime/audio` 主链路
- 日志、诊断、状态快照
- 消费 `contracts` trait

不负责：

- 直接调用 Windows/Linux API
- 直接持有 Tauri UI 状态

### `host-windows`

职责：

- Windows 平台 trait impl
- 屏幕采集、音频、编码、显示器设置实际调用
- 将平台返回值转换成 `contracts` 共享模型

不负责：

- Host 会话状态机
- IPC server
- 前端壳逻辑

### `host-linux`

职责：

- Linux 平台 trait impl

当前状态：

- 结构预留
- V1 不要求实现完成

## 7. 前端模块设计

## 7.1 `desktop/ui/`

建议按 feature 划分：

- `pages/`
- `components/`
- `features/runtime-status/`
- `features/session/`
- `features/diagnostics/`
- `features/settings/`
- `stores/`
- `services/`

原则：

- 页面和组件不直接知道 IPC 细节
- IPC 交互由 `services/` 封装
- 状态汇总放到 `stores/`

## 7.2 `desktop/src-tauri/`

建议模块：

- `commands/`
- `host/`
- `state/`
- `diagnostics/`

建议职责：

- `commands/`
  - 暴露前端可调用的 Tauri command
- `host/`
  - 拉起、停止、重启 Host Runtime
  - 管理本地 IPC client
- `state/`
  - 保存宿主壳运行状态
- `diagnostics/`
  - 日志桥接、导出、故障诊断入口

## 8. 协议目录设计

`proto/` 不和任何前端、Rust 运行时代码混放。

建议目录：

```text
proto/
  common.proto
  device.proto
  pairing.proto
  media.proto
  session.proto
  input.proto
  ipc.proto
```

后续如果再增加：

- `diagnostics.proto`

也仍然放在 `proto/` 下，而不是塞进 `desktop/`。

## 9. 依赖方向

## 9.1 总体依赖图

```text
android
  -> proto generated code

desktop/ui
  -> desktop/src-tauri command surface

desktop/src-tauri
  -> host-ipc
  -> proto generated code

host-runtime
  -> host-contracts
  -> host-ipc
  -> proto generated code

host-windows
  -> host-contracts
  -> proto generated code

host-linux
  -> host-contracts
  -> proto generated code

host-ipc
  -> host-contracts
  -> proto generated code
```

更准确地说：

- `runtime` 依赖 `contracts`
- `windows/linux` 依赖 `contracts`
- `src-tauri` 依赖 `ipc`
- `runtime` 依赖 `ipc` 的 server 侧接口
- `src-tauri` 依赖 `ipc` 的 client 侧接口
- `windows/linux` 通过 trait impl 被 `runtime` 装配使用，但不反向依赖 `runtime`

## 9.2 Rust crate 依赖矩阵

| crate | 可依赖 |
| --- | --- |
| `host-contracts` | 无 Host 内部依赖 |
| `host-ipc` | `host-contracts`、`proto` 生成代码 |
| `host-runtime` | `host-contracts`、`host-ipc`、`proto` 生成代码 |
| `host-windows` | `host-contracts`、`proto` 生成代码 |
| `host-linux` | `host-contracts`、`proto` 生成代码 |
| `desktop-shell(src-tauri)` | `host-ipc`、`proto` 生成代码 |

## 10. 禁止依赖

下面这些依赖方向明确禁止：

1. `contracts -> runtime`
原因：
`contracts` 是抽象层，不能反向知道编排层。

2. `contracts -> windows/linux`
原因：
抽象层不能知道平台实现层。

3. `runtime -> src-tauri`
原因：
Host Runtime 不能依赖桌面壳。

4. `runtime -> ui`
原因：
Host Runtime 不能持有前端表现层概念。

5. `windows/linux -> runtime`
原因：
平台实现层不能反向依赖会话编排层，否则 trait 边界会失效。

6. `ui -> windows/linux`
原因：
UI 不能直接接平台实现。

7. `src-tauri -> windows/linux`
原因：
桌面壳只能通过 Host Runtime 和 IPC 交互，不能绕过 runtime 直连平台层。

8. `ipc -> windows/linux`
原因：
IPC 只负责传输，不负责平台能力。

9. `proto -> runtime/contracts/windows/linux/ui`
原因：
`proto` 只作为协议源或生成代码输入，不反向依赖业务模块。

## 11. 初始化顺序

## 11.1 桌面端启动顺序

建议顺序：

1. 启动 `Tauri Shell`
2. 初始化 `desktop/ui`
3. `src-tauri` 检查 Host Runtime 是否已运行
4. 如果未运行，则拉起 `host-runtime`
5. Host Runtime 初始化 `contracts` 依赖的实现装配
6. Host Runtime 建立 IPC server
7. `src-tauri` 连接 IPC client
8. `src-tauri` 拉取 `RuntimeStatus` 与 `CapabilitySnapshot`
9. `desktop/ui` 展示 ready 状态

## 11.2 Host Runtime 初始化顺序

建议顺序：

1. 加载配置
2. 初始化日志与诊断
3. 装配平台实现
4. 建立 `CapabilityCache`
5. 初始化 `runtime/video`
6. 初始化 `runtime/audio`
7. 建立 IPC server
8. 进入 `READY`

## 11.3 会话建立顺序

建议顺序：

1. 控制连接认证通过
2. 拉取或确认 `DeviceSnapshot`
3. 接收 `SessionIntent`
4. 生成 `session_id`
5. 进入 `NEGOTIATING`
6. 装配视频/音频参数
7. 准备 `cap/audio/encode/display/input`，并记录 `history_display_mode` / `history_audio_output_setting`
8. 进入 `PREPARING`
9. 完成 WebRTC offer/answer
10. 进入 `STREAMING`

## 12. V1 最小落地模块

如果只按 V1 最小闭环先起工程，第一批必须先建的是：

1. `proto/`
2. `desktop/host/contracts/`
3. `desktop/host/ipc/`
4. `desktop/host/runtime/`
5. `desktop/src-tauri/`
6. `desktop/ui/`
7. `desktop/host/windows/`
8. `desktop/host/windows/input/`

可以先只预留但不深做：

- `desktop/host/linux/`
- `desktop/host/linux/input/`

但从目录上仍然建议一起建出来，避免后面再搬迁。

- `docs/05-模块与目录设计.md`
