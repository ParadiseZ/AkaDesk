# AkaDesk 数据流转流程图

## 1. 文档目的

本文档只描述运行时数据和控制流，不重复技术选型细节。重点说明：

- 启动过程
- 连接过程：由主控发起到被控
- 断开过程：主控主动断开
- 断开过程：被控主动断开或异常断开

桌面端在本文中明确拆成两部分：

- `Tauri Shell`
- `Host Runtime`

其中：

- `Tauri Shell` 负责 UI、配置、日志展示、拉起和监控 Host
- `Host Runtime` 负责会话、媒体链路、能力编排
- `Windows Platform Adapter` 负责实际平台能力调用

## 2. 运行时参与方

```mermaid
flowchart LR
    A["Android Controller App"] --> B["LAN Discovery / Control Plane"]
    B --> C["Tauri Shell"]
    C --> D["Local IPC<br/>interprocess + Protobuf"]
    D --> E["Host Runtime"]
    E --> F["Platform Contracts"]
    F --> G["Windows Platform Adapter<br/>cap / audio / encode / display / input"]
    E --> H["WebRTC Data Plane"]
```

说明：

- Android 不直接和 Tauri UI 交换媒体数据
- Tauri 不进入媒体主链路，只负责本地控制和状态展示
- 平台实际调用发生在 `Windows Platform Adapter`

## 3. 启动过程

### 3.1 启动时序图

```mermaid
sequenceDiagram
    participant U as User
    participant T as Tauri Shell
    participant I as Local IPC
    participant H as Host Runtime
    participant W as Windows Platform Adapter

    U->>T: 启动桌面端
    T->>H: 拉起 Host Runtime 进程
    H->>I: 建立本地 IPC 服务
    T->>I: 建立本地 IPC 客户端连接
    T->>H: 请求运行时状态
    H->>W: 查询显示器 / 音频设备 / 能力信息
    W-->>H: 返回平台能力快照
    H-->>T: 返回 Host 状态 / 能力摘要 / 诊断信息
    T-->>U: 展示桌面端就绪状态
```

### 3.2 启动后的职责边界

- `Tauri Shell`：
  - 拉起 Host
  - 建立本地 IPC
  - 展示状态和日志
- `Host Runtime`：
  - 初始化运行时
  - 加载平台实现
  - 聚合能力快照
- `Windows Platform Adapter`：
  - 查询显示器、音频设备、编码能力
  - 提供平台初始状态

## 4. 连接过程

## 4.1 主控到被控的连接总览

```mermaid
flowchart TD
    A["Android Controller"] --> B["LAN Discovery / Device Selection"]
    B --> C["Control Plane Handshake"]
    C --> D["Tauri Shell updates UI"]
    C --> E["Host Runtime creates session"]
    E --> F["Platform Adapter prepares cap/audio/encode/display/input"]
    E --> G["WebRTC offer / answer / ICE"]
    G --> H["Video / Audio / Input channels ready"]
```

## 4.2 连接时序图

```mermaid
sequenceDiagram
    participant A as Android Controller
    participant T as Tauri Shell
    participant I as Local IPC
    participant H as Host Runtime
    participant W as Windows Platform Adapter

    A->>H: 局域网发现 / 连接请求
    H-->>A: 设备信息 / 能力摘要 / 握手响应
    H-->>T: 推送待连接状态
    T-->>I: 读取连接状态变更
    T-->>T: 更新桌面端 UI

    A->>H: 发起会话建立 / 能力协商
    H->>W: 准备采集 / 音频 / 编码 / 显示设置
    W-->>H: 返回准备结果

    H->>A: 返回 WebRTC Offer 或握手参数
    A->>H: 返回 Answer / ICE / 媒体参数
    H->>W: 启动屏幕采集 / 音频采集 / 编码
    W-->>H: 输出编码后媒体数据
    H-->>A: 通过 WebRTC 发送视频 / 音频

    A->>H: 发送输入事件
    H->>W: 应用输入事件
    W-->>H: 输入执行结果

    H-->>T: 推送已连接状态 / 码率 / 分辨率 / FPS / 错误事件
    T-->>T: 展示连接状态和诊断信息
```

### 4.3 连接阶段的数据流向

- 控制流：
  - `Android Controller -> Host Runtime`
  - `Host Runtime -> Tauri Shell`
- 本地管理流：
  - `Tauri Shell <-> Host Runtime` 通过 `interprocess + Protobuf`
- 媒体流：
  - `Windows Platform Adapter -> Host Runtime -> Android Controller`
- 输入流：
  - `Android Controller -> Host Runtime -> Windows Platform Adapter`

关键原则：

- 媒体流不经过 `Tauri Shell`
- `Tauri Shell` 只消费状态、日志、诊断、配置结果
- `Host Runtime` 负责会话编排，不直接写平台调用细节
- 会话中的“分辨率修改”指目标显示器分辨率修改
- 分辨率修改允许按显示器设置重配 + 采集/编码重配处理，必要时重建链路
- 显示器模式变更应显式区分 `requested_display_mode` 和 `history_display_mode`

## 5. 主控主动断开过程

```mermaid
sequenceDiagram
    participant A as Android Controller
    participant T as Tauri Shell
    participant H as Host Runtime
    participant W as Windows Platform Adapter

    A->>H: 发送断开请求
    H->>W: 停止采集 / 编码 / 输入会话
    W-->>H: 释放平台资源
    H-->>A: 返回断开确认
    H-->>T: 推送会话结束状态
    T-->>T: 更新 UI 为已断开
    H-->>H: 清理会话状态 / 保留运行时待机
```

断开后的预期状态：

- `Host Runtime` 继续存活
- `Tauri Shell` 继续存活
- 平台采集和编码资源被释放
- 显示器模式恢复到 `history_display_mode`
- 桌面端回到待连接状态

## 6. 被控主动断开或异常断开过程

## 6.1 被控主动断开

```mermaid
sequenceDiagram
    participant T as Tauri Shell
    participant H as Host Runtime
    participant W as Windows Platform Adapter
    participant A as Android Controller

    T->>H: 用户点击断开 / 停止服务
    H->>W: 停止采集 / 编码 / 输入会话
    W-->>H: 释放平台资源
    H-->>A: 发送会话关闭通知
    H-->>T: 推送已断开状态
    T-->>T: 更新 UI
```

## 6.2 被控异常断开

```mermaid
sequenceDiagram
    participant W as Windows Platform Adapter
    participant H as Host Runtime
    participant T as Tauri Shell
    participant A as Android Controller

    W-->>H: 返回采集失败 / 编码失败 / 设备丢失
    H-->>H: 标记会话异常
    H-->>A: 发送错误或断开通知
    H-->>T: 推送错误事件 / 断开原因 / 诊断信息
    T-->>T: 展示错误并回到待连接状态
    H->>W: 清理平台资源
```

异常断开后的处理原则：

- 平台异常先由 `Platform Adapter` 上报
- 会话是否终止由 `Host Runtime` 决定
- UI 呈现和用户提示由 `Tauri Shell` 负责

## 7. 状态图

### 7.1 会话状态图

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Discovering: 主控发起发现
    Discovering --> Negotiating: 选中被控并发起连接
    Negotiating --> Preparing: Host 完成能力协商
    Preparing --> Streaming: WebRTC 建立完成
    Streaming --> Disconnecting: 任一侧发起断开
    Disconnecting --> Idle: 资源释放完成

    Negotiating --> Failed: 握手失败
    Preparing --> Failed: 平台准备失败
    Streaming --> Failed: 采集/编码/链路异常
    Failed --> Idle: 清理并回待机
```

说明：

- `Idle`：待连接状态
- `Discovering`：发现设备和拉取能力摘要
- `Negotiating`：握手、能力协商、会话建立
- `Preparing`：Host 准备采集、音频、编码、显示设置
- `Streaming`：视频、音频、输入链路已就绪
- `Disconnecting`：进入资源释放和会话清理
- `Failed`：异常中止，等待回收并回待机

### 7.2 Host Runtime 运行状态图

```mermaid
stateDiagram-v2
    [*] --> Starting
    Starting --> Ready: IPC 和平台快照初始化完成
    Ready --> SessionActive: 接收到连接并建立会话
    SessionActive --> Ready: 正常断开
    SessionActive --> Error: 运行时异常或平台异常
    Error --> Ready: 清理完成且运行时仍可服务
    Ready --> Stopping: Tauri 请求退出
    SessionActive --> Stopping: 强制停止
    Stopping --> [*]
```

说明：

- `Starting`：Host 进程启动并初始化 IPC 与平台能力
- `Ready`：Host 存活且可接受连接
- `SessionActive`：存在活跃控制/媒体会话
- `Error`：会话或平台异常，但进程仍存活
- `Stopping`：响应 Tauri 退出或停止指令

## 8. 流程与状态映射表

| 流程阶段 | Android Controller | Tauri Shell | Host Runtime | Platform Adapter |
| --- | --- | --- | --- | --- |
| 桌面启动 | 未参与 | `Booting -> Ready` | `Starting -> Ready` | `Initializing -> Ready` |
| 主控发现被控 | `Idle -> Discovering` | `Ready` | `Ready` | `Ready` |
| 主控发起连接 | `Discovering -> Negotiating` | `Ready -> ConnectingView` | `Ready -> Negotiating` | `Ready` |
| Host 准备平台能力 | `Negotiating` | `ConnectingView` | `Negotiating -> Preparing` | `Ready -> Preparing` |
| WebRTC 建立成功 | `Negotiating -> Streaming` | `ConnectingView -> SessionActiveView` | `Preparing -> Streaming` | `Preparing -> Active` |
| 主控发送输入 | `Streaming` | `SessionActiveView` | `Streaming` | `Active` |
| 主控主动断开 | `Streaming -> Disconnecting -> Idle` | `SessionActiveView -> Ready` | `Streaming -> Disconnecting -> Ready` | `Active -> Releasing -> Ready` |
| 被控主动断开 | `Streaming -> Idle` | `SessionActiveView -> Ready` | `Streaming -> Disconnecting -> Ready` | `Active -> Releasing -> Ready` |
| 平台异常断开 | `Streaming -> Failed -> Idle` | `SessionActiveView -> ErrorView -> Ready` | `Streaming -> Failed/Error -> Ready` | `Active -> Error -> Releasing -> Ready` |
| 桌面退出 | 未参与 | `Ready -> Stopping` | `Ready/SessionActive -> Stopping` | `Ready/Active -> Releasing -> Stopped` |

补充说明：

- `ConnectingView`、`SessionActiveView`、`ErrorView` 是 Tauri UI 展示态，不等于 Host 内部会话态。
- `Preparing`、`Active`、`Releasing`、`Error` 是 Adapter 侧资源态，用来描述平台能力的资源占用情况。
- Host Runtime 的 `Ready` 表示“可服务”，不代表一定有活跃会话。

## 9. 关键边界总结

### 9.1 Tauri Shell

负责：

- 拉起和监控 Host
- 建立本地 IPC
- 展示状态、日志、错误、配置

不负责：

- 不转发视频音频主数据
- 不直接调用平台采集或输入 API

### 9.2 Host Runtime

负责：

- 会话状态机
- 协议握手和能力协商
- WebRTC 会话编排
- 聚合平台结果并对外提供稳定服务接口

不负责：

- 不直接调用 Windows/Linux API
- 不承载桌面 UI

### 9.3 Platform Adapter

负责：

- 屏幕采集
- 音频采集
- 编码能力接入
- 输入注入
- 显示器设置读取和应用

不负责：

- 不负责 IPC
- 不负责会话状态机
- 不直接对前端暴露
