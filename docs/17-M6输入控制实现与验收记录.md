# M6 Android 控制 Windows 输入

## 本轮交付

手机点按电脑画面发送左键，拖动发送鼠标移动与左键保持，操作栏提供右键、上下滚轮和电脑键盘。键盘面板支持中文、表情等 Unicode 文字、常用按键和组合键、左右横向滚轮。Android 外接键盘映射到 Windows 虚拟键；手机返回键、音量键等系统按键留在本地。

“我的 → 按键映射”和远程键盘里的“编辑映射”可新增、修改、删除、重置常用按键，支持 Ctrl、Alt、Shift、Win 组合，最多 30 个映射。配置保存在手机 SharedPreferences，新建配置读取器会加载已保存内容；无配置或无效配置使用默认映射。

本轮对应开发里程碑 M6。画面仍来自 Windows 主显示器；没有增加复杂手势、手柄输入、显示器切换或显示模式修改。

## 实现链路

| 层次 | 实现 |
| --- | --- |
| 协议 | `proto/input.proto` 增加文字、释放和结果消息；按键使用 Windows VK，滚轮按格计数，正 Y 向上、正 X 向右。`SessionSnapshot.input_enabled` 表示会话已准备输入。 |
| Host 能力 | Windows 实现 `InputCapabilityQueryPort` 和 `InputInjectionPort`，通过原生 `SendInput` 注入鼠标、滚轮、按键、UTF-16 字符。其他平台保持输入不可用。 |
| 会话 | 完成认证、配对及启动授权后，根据 `enable_input` 准备输入。Android 等待设备能力快照再发启动请求，避免正式界面先启动、后拿到输入能力的时序问题，也保留旧 Host 的仅观看连接。 |
| 传输 | 与影音共用 PeerConnection，Host 建立可靠、有序的 `input` DataChannel，协议名 `akadesk.input.v1`。二进制 Protobuf 输入返回同序号 `InputResult`。 |
| 校验 | 通道绑定单一会话；仅活跃 Streaming 且启用输入的会话可注入。所有输入共用递增非零序号，拒绝重放、未知枚举、NaN、越界坐标及过大消息。 |
| Android | 画面按实际视频宽高比适配，输入坐标只来自视频矩形。通道状态和发送操作在主线程串行执行；WebRTC 原生回调只复制消息并异步投递，避免持锁调用 JNI 时与原生回调互相等待。 |

Host 单条输入最多 16 KiB，文字最多 4096 个 UTF-8 字节且不允许 NUL，坐标限定在 `[0, 1]`，滚轮单轴绝对值不超过 10 格。Android 发送队列积压超过 64 KiB 时关闭输入通道并提示重新连接，避免持续执行过时操作。

Windows 在当前 DPI 下读取主屏物理尺寸，再映射到虚拟桌面绝对坐标。按键和鼠标按钮按会话登记；重叠组合键共享修饰键需求，清理只释放本会话登记的输入。注入失败后停止继续注入并尝试释放，释放失败保留登记供后续清理重试。

触控取消、第二个手指按下、手机进入后台、打开或关闭键盘、视频停滞、主动断开都会请求释放。Host 在 PeerConnection 断开、通道关闭、会话结束时释放。过期回调和旧会话清理不能操作新会话。进程强制终止、UAC 安全桌面等情况未纳入本轮实机验收。

## 2026-10-10 验证结果

- Android Debug APK、测试 APK 构建通过，31 项单元测试通过，包括能力快照到达前的启动排队、仅观看兼容、映射校验、硬件键码转换。
- Windows Host 工作区 29 项测试通过，包括输入授权、会话绑定、重放和非法消息拒绝、原生失败清理、旧回调隔离；原有一项真实 WASAPI 测试默认忽略，本轮没有重跑音频端点验收。测试需把项目 FFmpeg DLL 目录加入 PATH；Linux 留有既有未使用依赖警告，未做 Linux 实机验证。
- realme RMX5060 经实际 WebRTC 连接控制 Windows 专用验收窗口：左键点按与拖动、右键、纵向及横向滚轮、`AkaDesk中文🙂`、Ctrl+C、Ctrl+F9 均到达原生窗口。Ctrl+C 被窗口记录一次。
- 有意保持 F8+Shift 和左键后发送 StopSession，窗口收到相应释放事件，结束时 Shift、Ctrl、Alt、Win、F8、左键的系统状态均未按下。
- 14 条输入均收到成功回执。最终一次数据为 `[37,14,12,16,15,17,18,32,21,22,21,20,21,26]` ms，中位数 21 ms，范围 12–37 ms。这是手机发送到 Host 注入成功回执的往返时间，不是操作到新画面显示的延迟，也不是长期负载指标。
- 正式 MainActivity/Compose 界面测试通过，实际触控拖动、右键、滚轮、文本框发送 `UI中文🙂`、断开及会话清理成功。Windows 原生窗口记录收到上述 Unicode 文字，测试输入结束后没有遗留按键。
- 映射编辑器真机测试覆盖新增、修改、删除、重新读取持久配置，并在结束时恢复原映射。

以上三项 Android instrumentation 用例均为真实手机运行。专用窗口可能同时收到本地鼠标事件，因此验收不把累计鼠标移动次数当作远程帧率或可靠性指标。游戏、管理员窗口、UAC、不同 DPI/多显示器布局、外接实体键盘、长期网络抖动仍需单独验收；本轮证明的是普通 Windows 桌面窗口的基础闭环。

## 重跑入口

在 `desktop/host` 使用全局 Cargo，清空有问题的 sccache wrapper，并把 `third_party/ffmpe-win64-gpl-shared/bin` 加入 PATH：

```powershell
cargo test --workspace --offline
cargo build -p host-runtime --example m6_android_fixture --offline
```

在 `android` 构建：

```powershell
.\gradlew.bat --offline :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest
```

安装上述 Debug APK 和测试 APK 后，用 `adb -s <serial> reverse tcp:46671 tcp:46671` 转发控制端口。每次验收启动 `m6_android_fixture.exe <全新的临时目录>`，读取其中 `android_fixture.json` 的 `hostId / pairCode / x / y`，作为 instrumentation 参数 `m6HostId / m6PairCode / m6X / m6Y`。

测试类位于 `android/app/src/androidTest/java/top/akadesk/app/controller/`：

- `M6InputInstrumentedTest`：有序事件、组合键、回执时间、停止确认。
- `M6InputUiInstrumentedTest`：正式界面的触控和键盘操作、断开清理；测试结束只删除本次临时 Host 的历史和配对记录。
- `InputProfileInstrumentedTest`：映射编辑和持久化，结束恢复原配置。

使用 `adb -s <serial> shell am instrument -w -r -e class <完整测试类名> ... top.akadesk.app.test/androidx.test.runner.AndroidJUnitRunner`。前两项缺少临时 Host 参数时跳过，不能计为实机成功。每个远控用例使用新 fixture，避免结束会话刷新临时验证码后的复用错误。

Fixture 只允许向自己的原生窗口注入；窗口失去前台焦点时拒绝输入，释放操作仍允许执行。应先将专用窗口放在前台。Fixture 180 秒或临时目录出现 `stop` 文件后停止、保存 `input_probe_final.json` 并恢复原光标；最终 JSON 需要检查字符、按键事件与 `held` 状态。Windows 屏幕采集需要正常桌面权限，受限环境的 BitBlt 失败不应算作输入故障。

Fixture 使用独立设置目录，不修改已安装 Host 的配置。私有临时数据放在忽略目录 `.codex_tmp/m6/`，不提交验证码和配对令牌。验收完成后移除本次 ADB reverse。
