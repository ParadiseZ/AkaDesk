# 14-桌面端被控功能(ui)实现记录

## 1. 文档目的

本文档用于记录 AkaDesk 桌面端远程协助壳当前已经实际落地的功能、涉及文件、验证方式和明确边界。

它解决的是：

- 当前桌面端到底已经做了什么
- 哪些内容只是 UI 预留，哪些已经接到真实 `Tauri Shell <-> Host Runtime` 设置与消息链路
- 本轮关于验证码、免密、双重验证的设计与实现进展到了哪里
- 后续继续补桌面端时，应该从哪些文件接着做

本文档是实现记录，不替代协议设计、状态机定义或里程碑文档。

## 4.3 验证码与验证方式

当前桌面端已经接到真实 Host 设置字段：

- `verification_mode`
- `temporary_verification_code`
- `custom_verification_code`
- `refresh_temporary_code_after_controlled_end`

当前远程页行为为：

- `临时`
  - 展示临时验证码
  - 可从设置菜单立即刷新
  - 可切换“被控结束后自动刷新”
- `自定义`
  - 不显示具体验证码
  - 只显示 `已设置自定义验证码 / 未设置自定义验证码`
- `使用两种`
  - 展示临时验证码
  - 文义上表示本次连接要先校验临时验证码，再校验自定义验证码

自定义验证码当前只允许在设置页修改，不在远程页修改。

## 4.4 设置页

当前设置页顶部已经改成与远程页一致的页签样式：

- `常规`
- `安全`

### `常规`

已经接到桌面壳本地设置：

- `启动页`
- `开机自启`
- `最小化到托盘`
- `启用桌面通知`

行为已经固定为：

- 改动后直接异步保存
- 不再保留单独保存按钮
- 启动页选项直接由 `router.ts` 里的同一份路由数据转换得到

### `安全`

已经接到 Host 设置：

- `远程协助连接本设备的方式`

当前选项包含：

- `验证码`
- `免密`
- `双重验证`

其中文义固定为：

- `验证码`
  - 设备 ID + 验证码即可发起连接
- `免密`
  - 不要求验证码
  - 由被控端同意后建立连接
- `双重验证`
  - 设备 ID + 验证码校验通过后
  - 仍需被控端明确同意

当选择 `验证码` 或 `双重验证` 时，当前页会展开：

- `自定义验证码`
- `修改` 按钮

点击后会弹出自定义验证码编辑框，限制为 8 位以内数字或字母。

对应文件：

- `desktop/ui/src/pages/SettingsPage.vue`

## 4.5 主控态 / 被控态窗口

当前桌面壳已经按连接角色切整窗：

  - `ACCESS_CODE`

  - `ACCESS_CODE_AND_CONSENT`

也就是说，本轮主要还是把：

- 桌面端 UI
- Host 设置模型
- 本地 IPC 同步

先定住并写清楚。

真正首先应闭环的仍是：

- `验证码` 连接流程

在此基础上，再逐步把：

- `免密`
- `双重验证`

接成真实控制流。

## 8. 后续继续时的建议切入点

如果下一步继续补桌面端，建议按下面顺序接：

1. 先把 `验证码` 连接流程完整接通到真实握手结果
2. 把 `免密` 的被控端确认流程接到真实控制层事件
3. 把 `双重验证` 的“先验证码、后同意”闭环补齐
4. 把主控态整窗接到真实视频渲染面板
5. 把历史 / 收藏 / 已配对切到真实数据源
6. 再补文件传输和发现页
